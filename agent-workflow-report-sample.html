Agent Workflow Diagnostic

为 AI 技术视频创作者设计的 Agent 工作流

诊断对象是一个面向程序员与开发者受众的 AI 技术内容创作者。核心矛盾不是剪辑，不是配音，而是"选题找素材"过慢，导致从发现题目到发布经常超过 3 天，其中约 1 天消耗在找题、判断题、补素材和决定拆解角度。

副业模式
B 站商单 + YouTube 创作收益
核心瓶颈
选题找素材
最强目标
找到最可能带来播放增长的题
内容定位
原理拆解 / 技术科普
01

工作画像

你不是泛 AI 资讯号。你的竞争力在于把新产品和新趋势，翻译成程序员能理解的技术方向判断。

Audience

核心受众

程序员、开发者。你的内容必须帮助他们理解未来技术方向，而不是只知道"今天又发了个新功能"。

Selection Logic

选题判断逻辑

优先关注 AI 新产品与新趋势，尤其是 X 上讨论突然变多、并且有明显争议与传播性的事件。

Teaching Style

表达风格

你更适合"用具体案例带出原理"，尤其偏爱和旧方案对比后差异明显的案例，以此建立技术主线。

02

流程地图

当前流程最大的浪费不是执行，而是前置判断。你在投入实测和脚本前，缺少一个稳定的研究员层。

1
发现信号

刷 X、公众号、其他创作者内容，捕捉 AI 新产品或新趋势。

2
判断值不值得做

主要依据是讨论度、传播性，以及是否可能带来播放增长。

3
补关键素材

需要产品实测截图、录屏、体验过程，但经常不知道该测哪些功能最值得拍。

4
确定拆解角度

想做原理拆解 / 技术科普，但常卡在"不知道最值得讲的技术主线是什么"。

5
生成视频判断

在多个候选题里做取舍，最难的是判断哪个题播放潜力更高。

6
进入脚本与制作

一旦题定下来，才进入口播逻辑、实测、脚本与后续制作。

03

诊断结论

你当前最该接入的不是"全自动做视频 Agent"，而是"选题研究员 Agent"。先把研究前置层做强。

最值得优先自动化的环节

每天自动生成一份 3 分钟内看完的研究员简报，告诉你"今日最值得做的 1 个题"，并附带 3 个对创作者 / 从业者最有实际价值的看点。

不建议一开始自动化的环节

最终观点判断、是否立项、视频立场与表达风格。这些是账号辨识度所在，应该继续由你亲自把关。

04

推荐 Agent 工作流

下面不是工具清单，而是 3 条可落地的工作流。顺序已经按"投入产出比"排好。

每日选题研究员

从官方账号与 X 异动中，筛出最值得做的 1 个题。
P1
  • 输入: OpenAI、Google、Anthropic 官方动态；AI 大号；创始人；关键词流。
  • Agent 步骤: 监控新动态 → 识别讨论突然放大 → 判断传播性 → 汇总背景与关键事实。
  • 输出: 一段 3 分钟内看完的简报。
  • 人工审核点: 这个题是否符合你的账号定位，而不只是热点。
  • 自动化等级: 半自动，高价值，低风险。

技术主线拆解器

把"新闻"变成"值得讲清楚的原理"。
P2
  • 输入: 已选中的 1 个候选题、官方文档、讨论串、演示案例。
  • Agent 步骤: 判断最值得讲的技术主线 → 找出上一代方案 → 提炼新旧差异。
  • 输出: 一个适合口播展开的逻辑大纲。
  • 人工审核点: 讲解深度是否够，是否会滑向"新闻复述"。
  • 自动化等级: 半自动，中风险，强依赖你的审美与判断。

对比案例搜索器

自动找出新方案最直接的上一代方案，帮你建立对照。
P3
  • 输入: 某个新产品、新功能或新技术方向。
  • Agent 步骤: 搜索同类旧方案 → 归纳旧工作流 → 提炼替代关系。
  • 输出: 3 组新旧对照案例，附差异点与可讲性。
  • 人工审核点: 对照是否准确，是否会误导观众。
  • 自动化等级: 中等，适合作为工作流 2 的配套模块。
05

简报模板

这是最适合你当前阶段的标准输出。它必须先给结论，再给证据，不要写成流水账。

每日 3 分钟研究员简报
  1. 今日最值得做的 1 个题: 用一句话直接下判断。
  2. 为什么现在值得做: 传播性、争议点、中文区空位、时效窗口。
  3. 3 个最值得讲的看点: 偏创作者 / 从业者的实际价值，而不是泛科普。
  4. 事件背景和关键信息: 官方动态、发布时间、外部讨论摘要。
  5. 建议下一步: 值得先测哪些功能，优先找哪些素材。
06

优先级排序

先解决选题研究，再解决技术主线，再解决对比案例。顺序不能反，否则你会继续被前置判断拖住。

Priority 1

每日选题研究员

直接减少你每天人工刷信息流和判断题的时间，预期能先吃掉 30% 到 50% 的选题时间。

Priority 2

技术主线拆解器

帮助你从"知道这是新闻"升级到"知道该怎么讲原理"，减少卡在结构设计上的时间。

Priority 3

对比案例搜索器

补齐新旧方案对照，让你的内容更像技术判断，而不是功能介绍。

07

启动计划

7 天内验证研究员简报的价值，30 天内形成完整工作流闭环。

7 天启动计划

  1. 列出第一批监控源: 官方账号、核心博主、创始人、关键词。
  2. 定义"值得做视频"的硬规则: 传播性、争议度、技术方向性。
  3. 做出第一版研究员简报模板，控制在 3 分钟内读完。
  4. 连续跑 3 天，观察简报是否真能帮你缩短判断时间。
  5. 记录每条简报最终是否立项，建立反馈闭环。

30 天升级路线

  1. 把"是否立项"和"发布后的播放表现"回写，形成选题评分数据。
  2. 增加"技术主线拆解"模块，让每个候选题自动生成口播逻辑大纲。
  3. 增加"上一代方案识别"模块，自动提供对比案例池。
  4. 逐步把工作流沉淀成固定 SOP，减少你每次从零判断。
  5. 最终目标不是全自动发片，而是稳定做出更高命中率的题。
08

边界判断

不是所有环节都应该交给 Agent。下面这条边界非常关键。

适合 Agent

高频、结构化、前置研究任务

  • 监控官方动态与讨论异动
  • 筛出候选题并排序
  • 汇总事件背景和关键事实
  • 找上一代方案和对照案例
不应外包

账号观点与表达辨识度

  • 最终立项判断
  • 视频观点与站位
  • 讲解层次和个人表达节奏
  • 对技术方向的最终结论
报告结论

你的第一优先级不是"做视频 Agent"，而是"做选题研究员 Agent"。先让 Agent 帮你把值得做的题选准，再谈后面的脚本、实测和规模化。
